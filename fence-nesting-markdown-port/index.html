MyST fence nesting comparison: modernize-use-auto

Both links open the complete Extra Clang Tools documentation built from llvm/llvm-project PR head 14370d30852fc7923f3bcca3421f9b898e3cc680 with its own clang-tools-extra/docs/conf.py and the shared utils/docs/llvm_sphinx configuration (Furo theme, MyST colon_fence and substitution), using the pinned versions in llvm/docs/requirements.txt. The two builds differ only in clang-tools-extra/docs/clang-tidy/checks/modernize/use-auto.md. In the current form, each {option} directive uses a 4-backtick fence around a nested 3-backtick c++ block, so the Options section renders two option entries with their code examples. In the requested form, the directive uses 3 backticks and the code block uses 4. A closing fence only needs to be at least as long as the opening fence, so the inner closing ```` line closes the outer 3-backtick {option} fence early. The trailing Default is ... line then falls outside the option, the leftover ``` opens a new code block that swallows the whole RemoveStars option as raw text, and the {option}`RemoveStars` cross-reference no longer resolves.

  • Current form (option fence 4 backticks, code fence 3)
  • Requested form (option fence 3 backticks, code fence 4)

The rest of use-auto.md is identical in both forms, so only the Options section is shown below.

Current form: Markdown source (Options section)

 172  ## Options
 173  
 174  ````{option} MinTypeNameLength
 175  If the option is set to non-zero, the check will ignore type
 176  names having a length less than the option value. The option affects
 177  expressions only, not iterators.
 178  Spaces between multi-lexeme type names (`long int`) are considered as one.
 179  If the {option}`RemoveStars` option (see below) is set to `true`, then `*s`
 180  in the type are also counted as a part of the type name.
 181  
 182  ```c++
 183  // MinTypeNameLength = 0, RemoveStars=0
 184  
 185  int a = static_cast<int>(foo());            // ---> auto a = ...
 186  // length(bool *) = 4
 187  bool *b = new bool;                         // ---> auto *b = ...
 188  unsigned c = static_cast<unsigned>(foo());  // ---> auto c = ...
 189  
 190  // MinTypeNameLength = 5, RemoveStars=0
 191  
 192  int a = static_cast<int>(foo());                 // ---> int  a = ...
 193  bool b = static_cast<bool>(foo());               // ---> bool b = ...
 194  bool *pb = static_cast<bool*>(foo());            // ---> bool *pb = ...
 195  unsigned c = static_cast<unsigned>(foo());       // ---> auto c = ...
 196  // length(long <on-or-more-spaces> int) = 8
 197  long int d = static_cast<long int>(foo());       // ---> auto d = ...
 198  
 199  // MinTypeNameLength = 5, RemoveStars=1
 200  
 201  int a = static_cast<int>(foo());                 // ---> int  a = ...
 202  // length(int * * ) = 5
 203  int **pa = static_cast<int**>(foo());            // ---> auto pa = ...
 204  bool b = static_cast<bool>(foo());               // ---> bool b = ...
 205  bool *pb = static_cast<bool*>(foo());            // ---> auto pb = ...
 206  unsigned c = static_cast<unsigned>(foo());       // ---> auto c = ...
 207  long int d = static_cast<long int>(foo());       // ---> auto d = ...
 208  ```
 209  Default is `5`.
 210  ````
 211  
 212  ````{option} RemoveStars
 213  If the option is set to `true`, the check will remove
 214  stars from the non-typedef pointer types when replacing type names with
 215  `auto`. Otherwise, the check will leave stars. For example:
 216  
 217  ```c++
 218  TypeName *my_first_pointer = new TypeName, *my_second_pointer = new TypeName;
 219  
 220  // RemoveStars = 0
 221  
 222  auto *my_first_pointer = new TypeName, *my_second_pointer = new TypeName;
 223  
 224  // RemoveStars = 1
 225  
 226  auto my_first_pointer = new TypeName, my_second_pointer = new TypeName;
 227  ```
 228  Default is `false`.
 229  ````
